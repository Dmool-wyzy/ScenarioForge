# Agent 协作与成本控制

## 结论

调度前审查能减少不必要的拆分，但单靠审查不能保证总成本下降。拆分任务会增加下游模型调用、上下文整理、结果审查和整合开销；任务很小或强依赖前序结果时，应由顶层 Agent 直接完成或顺序处理。

成本审查应复用顶层 Agent 已有的模型回合，不另开一次模型调用。模型价格无法可靠确认时，只说明相对成本等级和调用范围，不给出伪精确金额。审查负责决定“值不值得派发”，服务端限额负责决定“最多能花多少”；费用无法被限制或授权范围不清楚时，不派发。

## 当前实现边界

2026-11-11 源码包含独立工作区 Agent、版本化 Markdown 技能、仓库读写工具和隔离验证，详见[工作区执行说明](WORKSPACE_AGENT.md)。[本地 Runner](LOCAL_RUNNER.md)通过出站 HTTPS 领取操作并直接读写选定目录，支持停止、恢复和快照审查；以 `run --allow-commands` 启动后，可由任务创建者逐条批准无网络 Docker 命令。前端提供文档清单确认、方案/执行双页签、目录及详细进度。本版已部署到在线站点，服务、数据库迁移、Docker 隔离及无模型 HTTPS API 验收见[2026-11-11 上线记录](DEPLOYMENT-20261111.md)。下文的历史上线记录保留原日期和范围；新入口真实模型、用户电脑 Runner 远程执行及 GitHub Agent 完整流程仍待验收，当前边界见[本版说明](RELEASE_NOTES_20261111.md)。

- `Project.modelConfigEncrypted` 是团队项目共享模型配置，Key 仅由服务端解密和使用。
- 顶层 Project Agent 可直接聊天、调用 `run_research`，或向已配置个人模型并开启接收的成员派发最多两个子任务。组长也可配置自己的个人 Agent 并接收任务。每项先生成一次私有初稿；成员可追问、手动修改，确认提交后才交给顶层审核。成员对话和未提交初稿仅本人可见。
- 个人任务含初稿最多 6 次模型尝试，单次无工具、最多 2,048 输出 token；个人追问最多 2,000 字符，上下文最多 24,000 字符，交付最多 12,000 字符。服务端通过版本号和租约防止重复调用、重复提交及过期结果覆盖，失败不会自动重试。提交正文和顶层审核排队在同一事务中完成；模型审核仍消耗一次顶层轮次。
- Git 已支持通用非空仓库导入、人工编辑和上传、分支管理、审查合并及 GitHub 拉取推送。新增本地执行 Agent 可读取并提交项目文件，验证命令仅在隔离容器内运行；模型或容器未就绪时不宣称真实执行验收成功。
- `lib/prompts.ts` 已要求顶层 Agent 在同一模型回合评估依赖、并行收益、上下文、模型/工具调用及整合成本；简单或强依赖任务不拆分。该提示是决策约束，不是派发时的硬预算校验。
- 当前执行有服务端限制：顶层 Agent 最多 3 个回合、每回合最多 6,144 输出 token；研究规划 Agent 最多 24 个回合、每回合最多 2,048 输出 token；研究 MCP 最多 44 次工具调用；任务总时限 20 分钟；新搜索最多 12 次/包。Python 结构化模型每轮最多 72 个请求、累计最多 96,000 输出 token，单次按 schema 限制为 512–4,096 token。用量记入服务日志，不换算成美元。
- 输入 token 会记录但没有累计硬上限；目前没有按美元计价的项目月度预算。因此这些限制能压住调用轮数和生成长度，不能保证一个任务或项目的精确费用上限。
- Python 研究用量额度存在 MCP 单进程内存中，服务重启会清零；当前 MCP 只在 loopback 单进程运行。未来让 Python 研究预算跨 worker 或进程重启时，需改为数据库共享账本。

## 调度前审查

顶层 Agent 应在决定派发前评估：

1. 是否存在至少两个边界清楚、可独立交付的子任务；依赖链长或单个任务很小则不拆分。用户明确指定成员协作或验证派发时，可以在现有限额内派发一项任务。
2. 并行节省的时间和顶层上下文，是否高于每个下游的上下文准备、调用、审查及合并成本。
3. 下游所需上下文能否缩窄到明确的文件、证据或任务说明；不得默认复制完整聊天、个人空间或团队仓库。
4. 每个子任务的模型回合、工具调用、输出长度和运行时限是否有服务端可执行的上限。
5. 该任务是否新增未批准的服务、模型账户或数据去向；若是，先说明并取得相应授权。

审查结论可分为“直接处理”“顺序派发”“并行派发”。只有最后两类才创建下游任务。不能仅凭模型名推断价格；准确金额需要可信的服务商计价信息和实际 token 用量。对未知兼容服务，只能报告调用数/token 用量或成本等级。

## 目标结构

- **团队空间**：现有 `Project` 继续承载成员、共享资料和团队模型配置；团队 Agent 使用项目级 Key。只有项目授权范围内的资料进入任务上下文。
- **个人空间**：个人 Agent 配置按用户隔离并独立加密。Key、聊天历史及个人资料默认只有该用户可读；向团队共享资料或接收团队任务都需显式授权。
- **下游任务**：持久化父子关系、目标、交付格式、允许读取的上下文引用、执行身份、状态和资源上限。子任务不继承顶层会话；调用超限时停止并返回部分结果或待审批状态。
- **代码交付**：每个代码任务使用隔离工作区或 Git 分支，不直接改团队共享分支。顶层 Agent 检查变更和测试结果后再提出合并；保留可审阅、可拒绝和可回滚的差异。
- **远程 MCP**：在任务、成员身份、项目授权和隔离执行边界稳定后，再开放远程传输。当前 loopback/internal-token MCP 不作为外部 Agent 接入能力。

## 分阶段实施

1. **成本策略与任务契约（本地基线已完成）**：当前研究执行链已有模型回合、MCP 工具调用、输出 token、搜索和运行时限；Node 与 Python 会记录模型 token 用量，未知服务价格不折算为美元。离线测试覆盖超限停止和两种 API 协议的 token 参数，没有真实模型请求或数据库迁移。该限额尚未形成项目级美元预算，也未覆盖未来的团队/个人 Agent。
2. **团队 Agent 派发（已部署并验收）**：复用项目已有团队模型，单批最多两个独立文本子任务并行运行；服务端原子限制每个父轮次的派发数，子 Agent 一次模型调用、每项最多 2,048 输出 token。记录目标、显式上下文、结果、状态和用量；结果先回顶层审查，不直接修改共享内容。2026-11-08 隔离 MySQL 中的成员隔离、失败写入与租约接管后迟到结果拒绝测试通过；“申威课设”真实 DeepSeek 网页派发两个子任务、顶层汇总均成功。整轮 4 次调用、5,191 token，其中子任务仅 641 token；该样例不证明总费用下降。完整记录见 `VALIDATION.md`。
3. **个人 Agent 与权限（已部署，用户确认交付成功）**：个人模型配置和收件箱已部署，支持成员私有追问、编辑和确认提交。隔离 MySQL 验证成员隔离、过期恢复、调用上限、同时提交及顶层排队；浏览器夹具验证追问、编辑、提交、刷新。用户已确认 SHENWEI-INTERACT-1108B 的交互验证和交付完成。
4. **Git 工作区与审查**：文档交付的任务分支、差异审查、显式合并及 GitHub 推送已按历史记录验收；通用非空/私有仓库导入、人工文件编辑、分支管理及快进拉取/推送已有实现。本版另提供 Agent 在独立任务分支读写、静态检查与 Docker 验证的执行链路，已于 2026-11-11 部署；真实 GitHub Agent 修改 → 测试 → 人工合并的完整验收仍待完成。Git 子进程不继承应用密钥、不运行钩子；远程使用项目专用 SSH 部署密钥，严格校验主机公钥。当前仓库操作锁只适用于单 Web 进程；扩展多进程前必须改为共享锁。
5. **外部 Agent/MCP**：加入远程传输、成员认证、项目授权、限流与审计，再用外部客户端验收。

每阶段先完成本地实现和检查；数据库变更应先在独立测试库验收。若测试库不可用，不能把生产库当作测试环境；只有用户明确授权时，才可在生产备份后应用范围明确的迁移，并记录未覆盖的验证。新增付费服务、扩大模型调用范围或接入代码仓库凭据也需另行明确授权。
