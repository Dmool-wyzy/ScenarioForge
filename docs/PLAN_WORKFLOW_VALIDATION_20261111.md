## 最终行为

1. 首次输入和已有对话均可点击「生成方案文档」，使用现有目标、讨论、约束和资料生成实际保存的 `PLAN.md`、`TASKS.md`。用户仍可点击「发送」先讨论，或明确要求联网调研；方案生成操作本身不联网、不修改项目、不执行命令。
2. 研究文档展示真实文件，可预览、编辑、保存新版本，或下载单份/ZIP。没有研究计划时不展示虚构的 README、RESEARCH、SOURCES 待生成标签。方案注明尚未执行或验证。
3. 「使用这些文档继续执行」带入原始目标并预选当前研究包文档，展开技能选择并定位到执行要求。用户可以修改要求、选择技能、指定本地 Runner 或 GitHub，再点击「开始执行」。交接按钮本身不启动任务，下载文件不是交接前提。
4. 执行创建时固定所选技能的正文、版本与哈希；以后修改原文不改变已启动任务或恢复任务的技能。`PLAN.md` 和 `TASKS.md` 标为流程指导并说明用途。
5. 研究与文档在前，执行与验证在后。研究进度排除 `execution_*`；每张执行卡只展示同一 `executionId` 的执行事件。

## 保存与费用边界

方案任务使用既有队列和租约，不增加数据库迁移。状态依次为 `drafting_documents`、`documents_ready` 或 `documents_failed`；文件与事件在同一事务中保存。

- 单次结构化模型请求，无研究/执行工具、联网或自动重试。运行进程中断且租约过期时明确失败，需用户手动重新生成。
- 输入最多 50,000 字符，固定两份文档，每份模型正文最多 12,000 字符。结构无效、输出截断或超限时不把聊天回答当作已保存文件。
- 排队和提交时检查成员权限、任务互斥、编辑锁和阻塞问题；提交再检查租约、上下文版本及文件版本。手改保存过的 PLAN/TASKS 返回冲突，保留用户内容。
- 编辑方案、解锁方案和回答旧可选问题只保存更新，不隐式继续付费研究；普通研究的既有续跑行为保留。
- 服务端同时拒绝生成过程中启动或恢复执行，前端也禁用相应按钮。本地命令仍须逐条网页审批，Docker 和模型配置沿用既有配置。

用户实际提交方案任务后，事件已正确进入 `documents_started`，约一分钟后却以“服务暂时无法完成请求”结束。服务端记录显示模型返回了 `completed` 响应，包含符合方案结构的完整 `plan` / `tasks`；安装版本的 OpenAI SDK 随后对字符串执行对象属性检查，抛出 `TypeError`，因此文件未能保存。本次调用的认证和生成已成功，不能把这条报错归因为无效密钥或未配 Runner。

SDK 按响应的媒体类型选择 JSON 或文本解析；错误媒体类型，以及 JSON 对象被额外编码成 JSON 字符串，都可能造成此现象。原日志没有保留响应头，无法进一步断言网关当时具体使用了哪一种格式。

## 同日更新：可编辑文档清单

当前方案入口不再强制保存 `PLAN.md` / `TASKS.md` 两份文件。首次输入和已有对话先点击「预览文档清单」，在右栏调整文件名、用途与内容要点；支持添加模板、添加自定义文件、移除任意默认文件，最终保留 1–20 份。点击「确认并生成 N 份文档」后才排队调用模型。清单只是提案，尚未创建 Markdown 文件，也不出现在下游技能列表；正文保存后才可浏览、下载或交接。

推荐清单使用本地关键词规则：简单目标默认两份，明确涉及架构、接口、数据库、实验、风险、测试策略或里程碑时追加对应模板。它不调用模型、不联网，也不是语义规划或需求完整性判断。用户可以修改所有推荐，包括只生成一份自定义文档。联网研究的原文件计划规则仍独立保留，本次未改变搜索或 RAG 配置。

公开文档接口现在分为 `action=preview` 和 `action=generate`，生成须携带最新 `proposalId` 及最终清单。提案通过已有研究事件持久化，本次无新增迁移。预览后补充普通讨论、修改资料/文档、回答澄清或发生澄清超时，会使旧版本失效；页面保留编辑内容并要求显式重新预览。重复确认、旧提案、上下文和目标文件基线冲突均拒绝排队。所选目标有人工作业时拒绝覆盖，未选旧文件保留；模型必须精确返回所选文件集合，事务同时保存全部正文与事件。

正文生成仍为一次结构化请求，无搜索、工具调用或自动重试。每份模型正文最多 12,000 字符，合计最多 60,000 字符；确认清单最多 32,000 字符，组合输入仍受 50,000 字符限制。选择 20 份并不保证一次可生成 20 篇长文，超出限制须拆分目标。生成期间上下文、编辑状态或租约变化，拒绝保存过期结果，不自动再付费生成。

## 同日更新：双页签工作区

项目工作区现分为「方案与文档」和「执行工作区」，默认展示方案页签。方案页签保留对话及 Markdown 双栏；执行页签集中展示本地/GitHub 选择、技能、要求、进度、验证与差异。顶部吸附导航显示项目、当前工作方式、连接状态，以及本地目录的展开和复制操作；本人待审批命令会显示数量和进入执行区的入口。

两个面板持续挂载，通过隐藏切换，保留聊天草稿、清单编辑、Markdown 草稿及编辑锁、执行要求、技能勾选、Runner 选择和已打开的文件差异。隐藏区域继续接收更新，不滚动页面或抢夺焦点。「使用这些文档继续执行」自动切换至执行区并预填要求、选择实际保存的技能，仍须手动开始执行。全部活动任务展开；没有活动任务时展示最近一条，其余历史默认收起，展开后仍可查看差异、继续执行。连接说明和配对操作收进「连接与运行设置」。

切换页签仅用 `replaceState` 更新 `workspace=execution`，选择新项目/研究时清除此参数。文件链接和研究锚点优先打开方案区；通用定位 Hook 会先显示隐藏面板，再展开目标、聚焦并滚动。项目个人 Agent 收件箱默认收起，其任务深链仍自动展开；个人中心的模型设置保留原展开方式。本轮没有新增接口、数据库迁移、环境配置或真实模型调用。
