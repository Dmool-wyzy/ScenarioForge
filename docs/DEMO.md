# 演示脚本

## 准备

1. 按根目录 README 配置 `.env.local`、Prisma migration 和 Python 依赖。真实研究选择 searxng / ddgs / tavily；本地流程演示可用 mock，但必须说明搜索结果是测试数据。
2. 终端 1：在 `mcp-server` 执行 `uv run main.py`。
3. 终端 2：在根目录执行 `npm run dev`。
4. 打开 `http://localhost:3000`。

## 演示流程

1. 点击“软件项目示例”，展开约束条件，填写两周、3 人、低预算和 Next.js。
2. 可选上传 `.md` 或 `.txt` 课程要求，点击“开始研究”。
3. 展示左侧时间线及右侧文件计划：生成正文前，每份文件先列出名称、用途、优先级和内容要点；随后展示搜索 Provider、实际查询词、结果数量和证据卡。
4. 如果出现澄清卡片，解释提问原因并提交答案，展示研究继续。模型不一定每次都需要提问；活动策划示例更可能存在重要信息缺口。
5. 按实际文件计划查看文档。打开 `RESEARCH.md` 与 `SOURCES.md`，核对证据编号、来源和待确认事项；若场景规划了 `DECISIONS.md`，再核对 AI 建议与决策状态。
6. 在 `README.md` 点击“编辑 Markdown”，修改一项内容并填写修改说明，点击“保存并通知 Agent”。展示版本递增、解锁和后续 Agent 更新；原文必须保留。
7. 点击“当前文件”下载 Markdown，再点击“全部 ZIP”，解压核对当前工作区的实际文件清单。
8. 刷新浏览器，确认当前研究包与已保存文件恢复。
9. 在“继续与 Agent 对话”中输入“补充预算估算，保留现有内容”，确认同一研究会话继续；若预算值得独立成文，应先追加 BUDGET.md 的文件计划，再生成文档。

## 可复现的流程验证

在没有真实 API key 的环境中，先停止 Next.js，再运行 `npm run check:agent`。此命令以确定性的本地夹具验证规划、搜索、阻塞提问、回答恢复、文档生成与用户修改，分别覆盖 Chat Completions 和 Responses。测试文档明确标注为夹具，不代表真实研究结果。

## 常见演示问题

- 缺少变量：根据页面中文提示补齐 `.env.local`，重启两个服务。
- MCP 连接失败：确认 Python 服务监听 `127.0.0.1:8000`，两端地址与内部 Token 一致。
- 模型调用失败：核对服务商支持的模型名、base URL、所选 API 模式及 tool calling。
- 搜索失败：查看时间线的 Provider、错误码及原因；SearXNG 检查 URL 和 JSON 输出，DDGS 检查 Python endpoint，Tavily 检查 key/额度。修复后在对话区请求重试，单包搜索次数仍受上限约束。
- 阻塞问题超时：问题仍可回答，系统不会擅自使用没有安全默认值的答案。
- 锁已过期：编辑器保留草稿；取消后重新进入编辑并核对最新版本。服务端不会以旧版本覆盖新内容。
