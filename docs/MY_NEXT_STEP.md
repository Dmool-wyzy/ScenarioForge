# 我的下一步

2026-11-09，本地个人主页已接入；访问 http://localhost:3000 使用原有账号登录。公网网页需要单独发布本次代码才会显示新版。

## 使用

1. 在「我的项目」卡片点 1–5 星，默认 3 星，5 星最高。设置仅属于当前账号，刷新和再次登录后保留。
2. 同星级项目可拖动 ⋮⋮ 或点上下箭头，调整项目列表的显示顺序。任务推荐仍按下述工作规则计算。
3. 首页上方查看跨项目「我的下一步」：默认展示一个重点推荐和最多两个其他项目。可切换「等待中」、筛选项目、展开全部事项。
4. 点击事项中的动作进入具体个人任务、澄清问题、Git 交付或研究进度，相关折叠区域自动展开并定位。
5. 已明确截止日期的事项自动采用任务日期，卡片显示来源，无需重复填写。没有明确日期时，才显示「设置我的截止时间」，个人设置仅用于自己的排序与提醒。
6. 操作完成后根据实际工作状态更新待办；支持手动刷新、页面重新获得焦点时刷新，以及每 30 秒在可见页面刷新。点击卡片本身不会完成任务。

## 排序规则

- 仅可执行事项参与当前推荐；正在执行、等待仓库准备、等待创建者审查的事项单列为「等待中」。
- 首先比较个人项目星级；高星项目没有可执行事项时，继续推荐其他项目。
- 同星级依次比较：紧急程度（逾期、24 小时内、3 天内、普通）、明确阻塞流程、具体截止时间、进行中的事项、等待时长、稳定标识。
- 临近截止和已逾期事项在独立的提醒栏中展示，即便星级较低也不会被隐藏；「查看截止提醒」同时列出紧急的待处理与等待事项。
- 当前系统通过个人 Agent 授权接收分配，并无逐项接受/拒绝状态，因此直接使用现有分配结果，不增加重复接受步骤。

## 截止时间来源

- 只从任务描述（子任务的 `objective`）识别明确的截止日期，不读取任务上下文、项目或所属研究的目标与约束。任务描述中的明确日期优先于个人设置，并随交付进入 Git 审查；没有明确日期时可自行设置。
- 澄清问题、研究进度和仓库准备事项保留个人日期设置，不把问题中提到的日期或项目截止日期视作这些事项的截止时间。
- 支持 `2026-11-20`、`2026年11月20日 18:00`、`11月20日`，以及「明天」「下周五」「7天内」「两周内」等常见表达。正文需有截止、最晚或“某日前提交/完成”等明确要求；普通事件日期不会自动变成截止时间。
- 未写时区的日期按北京时间解释；仅写日期按当日结束处理，卡片会标明。未写年份采用对应任务创建时的年份。
- 相对期限固定以任务创建时间计算，刷新不会顺延。带时区偏移的 ISO 时间按偏移换算后以北京时间显示。
- 示例、否定要求、冲突日期、非法日期或「尽快」「下周」「两周左右」等无法确定的表达，不猜测具体截止时间；仍可设置个人日期。
- 任务明确日期期间，界面和接口都禁止个人日期覆盖或清除它。原个人设置保留，任务不再有明确日期时可继续使用。

## 当前接入的事项

- 自己的个人 Agent 任务：初稿待确认、失败待处理、超时对话恢复；执行中的任务进入等待列表。
- 创建者可处理的澄清问题及中断的研究；排队、执行中的研究进入等待列表。
- 自己已提交但尚未保存到 Git 的交付，以及创建者待审查的 Git 任务分支。
- 已提交交付但未准备工作区时，提醒创建者配置 Git；已合并交付不再推荐。
- Git 交付状态核对失败时显示提示，不把未知状态猜成待提交或待合并。其他项目及个人任务继续显示。
- 超过最近 50 条列表的旧任务和旧交付仍可通过待办入口定位，权限检查照常执行。
