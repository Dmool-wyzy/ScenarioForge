# 贡献记录与经验等级（第一版）

入口：个人中心 → 贡献记录。个人资料上方也展示等级卡片。全账号累计经验；项目筛选仅筛选时间线，不改变全局等级与贡献总数。

等级：Lv.1 探索者 0、Lv.2 参与者 100、Lv.3 实践者 300、Lv.4 共建者 700、Lv.5 中坚者 1500、Lv.6 领航者 3000、Lv.7 项目狂人 9999。达到门槛立即升级，最高等级继续积累经验；撤销贡献会重新计算等级。等级不会改变项目权限。

卡片依次采用浅绿、翡翠、青蓝、紫晶、浅金、深绿金、深色金光样式。逐级增加徽章、边框、纹饰和阴影；最高等级有缓慢扫光，系统设置减少动态效果时关闭。等级图鉴只预览，不会修改真实经验。

## 认可流程

- 项目创建者在贡献记录的「项目贡献审核」选择项目，展开交付内容，填写至少 10 个字的具体检查说明，确认贡献。
- 已提交的 Agent 任务交付 +30；任务初稿、对话、单纯提交暂不计分。使用 Agent 辅助不影响资格。
- 团队共享知识库中未归档的独立成果被认可 +10，归属到 `createdBy` 成员；普通收藏不算采纳。当前版本不对缺少可靠作者归属的工作区文件、任意 Git 提交发放经验。
- 审核他人的任务或共享成果 +10，和主贡献在同一事务记账。审核自己的成果不获得额外审查经验。
- 第一版将每个 `status=completed` 的研究包作为一个里程碑，由创建者确认。该研究包内至少有一项已认可任务或成果的当前成员 +20；仅有审查记录的成员不满足条件。补认参与者后可以再次确认里程碑，为新增成员补发，已有成员不重复获得。
- 没有从聊天文本推断“审核通过”，也没有给历史贡献自动补分。历史已提交任务、已完成研究和共享成果可以由创建者在上述入口确认。
- Git 存入、合并、推送不单独奖励。交付经认可统一计一次；跨类型的语义重复成果需要创建者审核时排除。

## 账本与撤销

新增 ContributionRecord 表，来源键和用户组成唯一键；经验值由服务端确定。事务使用 Serializable，发生并发冲突会有限重试。重复确认是幂等操作。

撤销任务/成果认定会同时撤销关联审查经验；如果成员不再有该阶段的有效任务或成果，回退该成员的里程碑经验。撤销里程碑会撤回该里程碑所有成员的奖励。重新认定恢复原账本记录，不新建重复奖励。已被认可但删除、归档或超出最近来源列表的记录仍可撤销。

归档资料只是资料管理动作，不等于撤销贡献认定；需在贡献审核中明确撤销。已离开或删除的项目仍保留过去的有效经验，但个人接口隐藏项目标题、贡献正文、审核理由和跳转链接。只有项目创建者可以管理本项目记录。

列表每页 20 条；审核候选显示每类最近 100 项来源，并保留已认可记录的撤销入口。第一版不做排行榜、经验衰减或等级权限。

## 验证

`scripts/check-contributions.ts` 必须使用 `.tmp/private/next-steps-test.env` 的隔离数据库，检查等级边界、来源验证、越权、并发去重、撤销联动、自审、里程碑参与条件和失去成员权限后的内容保护。

`tests/contributions.spec.ts` 使用网络桩验证筛选、源链接、审核和失败重试、撤销、全部等级样式、移动端以及减少动态效果。

数据库迁移：`20261109040000_contribution_levels`，仅新增表与外键。与现有服务端版本兼容。页面和接口需部署本版代码后才会在公网可用。
