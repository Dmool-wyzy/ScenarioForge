# Git 工作区：基础功能与后续计划

更新：2026-11-08。

## 已实现

在项目的「团队 Git 工作区」内，保留仓库连接、私有仓库导入、任务交付和推送流程，新增「仓库文件与版本」。

| 功能 | 操作与行为 |
| --- | --- |
| 文件浏览 | 按分支浏览目录、返回上级、按完整路径搜索；支持中文和空格路径 |
| 预览与下载 | UTF-8 文本按原始内容展示；二进制文件下载为原始字节；不执行仓库代码或渲染 HTML |
| 上传 | 支持多个文件和文件夹，保留相对目录；可指定目标目录；同名文件以显式 Git 提交替换 |
| 文件编辑 | 新建文本、修改、重命名、标记删除；提交前可逐项撤回 |
| Git 提交 | 待提交列表和提交说明；每批变更形成一次原子提交；作者记录当前成员，提交者为 ScenarioForge |
| 分支 | 从当前选中分支创建个人工作分支、切换浏览、查看相对 main 领先/落后数、删除已合并工作分支 |
| 历史 | 每页 25 次提交，展示作者、时间、说明及提交差异 |
| 审查合并 | 对比工作分支与 main；项目创建者查看差异后确认合并；冲突时撤销本次合并并保留原 main |
| 远程同步 | 检查 GitHub 连接，快进拉取关联分支，确认后推送 main；兼容远程 master 等分支映射 |
| 团队任务 | 保留原有的交付文档 → 任务分支 → 审查 → 合并 → 推送流程 |

## 使用步骤

1. 连接/导入仓库，或创建项目工作区。
2. 展开「团队 Git 工作区」，在「仓库文件与版本 → 分支与合并」输入名称，例如 `feature/login`，点击「创建我的分支」。
3. 在「文件」中上传文件/文件夹，或打开文件编辑。编辑完成后点击「加入待提交」。
4. 核对待提交列表，填写说明，点击「提交到当前分支」。到这一步只保存在服务器 Git 仓库。
5. 创建者选择该工作分支，点击「与 main 比较」，审查后「确认将分支合并到 main」。
6. 在上方检查 GitHub 连接，准备推送 main，再确认推送。Deploy key 需要具备写权限。
7. GitHub 上有新提交时，先检查连接，再「快进拉取远程更新」，然后刷新文件与分支。

工作分支实际命名为 `work/<成员ID>/<输入名称>`，隔离成员写权限。所有成员可读项目仓库；成员只能修改、删除自己的工作分支，创建者可管理所有工作分支。main 与 task/* 不允许通过文件编辑入口直接提交。任务分支仍使用交付审查入口。

## 当前边界

- 单个文件上传/预览/下载最多 1 MiB；单次最多 50 个文件、总计 4 MiB。仓库最多浏览 10000 个文件，目录或搜索最多显示前 300 项，可缩小搜索范围。
- 文件夹上传不解压 ZIP，不自动忽略 node_modules 等目录；请选择实际要提交的源文件目录。
- 草稿暂存在当前页面。切换分支/刷新文件会在有草稿时禁用；关闭或刷新整个页面会提示。切换项目等应用内部导航前，请先提交；暂不支持草稿跨页面保存。
- 不编辑符号链接、子模块及非 UTF-8 文本。Git LFS 只保留指针，不下载大文件本体。
- 通过网页创建的工作分支保存在服务器，合并后随 main 推送；暂不单独推送工作分支或获取所有远程分支。
- 大型差异超过约 500 KiB 时须使用 Git 客户端审查；网页会禁止该工作分支的合并。
- 删除文件和分支不会擦除 Git 历史。删除分支仅允许已合并分支。
- 本地/远程历史分叉时不会强制覆盖。已拉取的远程版本需在 Git 客户端完成合并；网页没有冲突编辑器。
- 当前锁适用于单 Web 进程；扩容到多进程/多实例前需增加跨进程仓库锁。

## 暂未实现、难度较高的功能

| 功能 | 主要工作与建议顺序 |
| --- | --- |
| 在线冲突解决 | 三方差异编辑、冲突标记检查、多人并发及中断恢复。建议优先于复杂 Git 操作实现 |
| 完整远程分支协作 | 获取所有远程分支、设置跟踪关系、分支推送及远程删除；需补充分支权限和审查策略 |
| GitHub PR 与代码评审 | PR 创建/更新、逐行评论、审批状态、保护分支和状态检查。需要 GitHub App 或用户 OAuth，现有 Deploy key 无法调用这些 API |
| Rebase / cherry-pick / revert | 提交选择、冲突状态机、可恢复操作记录；rebase 涉及历史改写，不能简单暴露为按钮 |
| 大仓库、LFS、子模块 | 流式上传下载、对象存储、配额、独立鉴权与异步任务；当前采用明确大小上限 |
| 多人同时在线编辑 | 草稿持久化、版本锁/协同算法、离线恢复和合并体验 |
| CI/CD 与网页运行代码 | 隔离执行环境、资源限制、构建任务、日志与凭据隔离；不能直接在 Web 进程执行导入的仓库代码 |
| 标签、Release、回滚界面 | 基础标签操作较简单；发布资产、版本回滚和与 GitHub Release 联动还需单独设计流程 |
