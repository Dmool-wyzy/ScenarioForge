# 2026-11-11 源码更新

本版将研究 Markdown 与工作区 Agent 接通：用户先确认文档清单和正文，再把保存的文档作为技能交给 Agent，在本地目录或 GitHub 任务分支修改文件，并查看验证与差异。项目界面分为「方案与文档」和「执行工作区」，避免把所有操作纵向铺开。

本次更新的是源码、数据库迁移、测试和文档，**没有部署服务器**。最近的在线部署记录仍为 2026-11-09；运行本版需由维护者准备环境、核对迁移并发布应用。

## 主要变化

- 文档生成采用「预览清单 → 编辑 → 确认生成」：默认推荐 `PLAN.md` / `TASKS.md`，按明确关键词建议更多模板；可增删、改名、修改用途与内容要点，最终保留 1–20 份。预览使用本地规则，不联网、不调用模型；正文生成一次请求，无自动重试。旧清单、重复确认、版本冲突和人工编辑目标受到保护，未选旧文件保留。
- Markdown 技能在任务启动时固定正文、用途、来源和版本。Agent 必须读取全部所选技能后才可写文件；下载可选。文档交接自动进入执行页签并带入要求，仍由用户手动开始执行，不自动合并或推送。
- 双页签保留聊天草稿、清单修改、Markdown 编辑和编辑锁、执行要求、技能勾选、Runner 选择及已打开差异。顶部显示项目、目录与连接状态，待审批命令有直达提示；当前任务展开，历史任务和连接设置默认收起。
- 本地 Runner 通过出站连接领取操作，直接修改选定的 UTF-8 文本目录；支持配对、撤销、心跳、停止/恢复和保存差异。目录展示使用 Runner 认证上报的真实路径，任务保留执行时目录快照；本地目录、操作事件及差异仅向任务发起者返回，也不进入共享研究模型上下文。
- 工作区 Agent 提供文件浏览、读取、变更、静态检查、隔离命令与差异审查。GitHub 模式使用独立任务分支，本地模式不要求 GitHub。Runner 用 `run --allow-commands` 启动且任务创建者逐条批准后，命令才会在本机无网络 Docker 容器执行；不会回退为宿主机命令。
- 操作进度记录等待模型、读技能/文件、写入、检查、命令审批与回执等真实事件和耗时，按任务隔离。修复开发服务调度回调未热更新的问题，以及成功模型响应使用非标准媒体类型或额外 JSON 编码时的解析问题；无效响应仍明确失败，不自动重试。

## 运行与配置

开发者按 [README](../README.md) 安装依赖，使用 [.env.example](../.env.example) 准备自己的 `.env.local` 与独立 MySQL。网页操作见[使用手册](USER_MANUAL.md)，本机配对与命令审批见[Runner 说明](LOCAL_RUNNER.md)，实现边界见[工作区 Agent 说明](WORKSPACE_AGENT.md)。

本版不更换模型、搜索或 Embedding 配置。项目模型配置优先，服务端默认配置作为未配置项目的回退；真实调用需要有效模型服务及额度。默认搜索仍为 Mock，不能作为外部事实；RAG 默认关闭，独立 Embedding 配置与质量验收可以后置，不阻塞文档技能执行。

当前源码有 14 条 MySQL 迁移，本版新增三条：

1. `20261110090000_workspace_execution`：执行任务、技能快照、租约与验证记录。
2. `20261110170000_local_runner`：Runner 配对、连接及文件/命令队列。
3. `20261111120000_local_runner_directory`：连接目录与执行时目录快照的两个可空字段。

文档清单和双页签不增加迁移。`npm run db:deploy` 会应用目标库全部待执行迁移，部署前应核对目标、备份及迁移状态；本次没有在生产库执行该命令。

## 部署与后续工作

1. 完成本版新入口的真实模型 + Docker + 人工审查联合验收，事先明确调用额度和测试范围。
2. 在独立环境验证后发布服务器，应用待执行迁移；GitHub 模式需配置服务器 Docker 权限及快照导出目录。本地模式由用户电脑运行 Docker，仍需从线上受信任的 HTTPS 地址验证 Runner 配对、断线和恢复。
3. 验收 GitHub Agent 从真实仓库读取、修改任务分支、测试到人工合并/推送的完整流程。已有导入、文件编辑、分支和同步功能不等于此项已完成。
4. 扩展依赖安装/缓存、多语言与较大工程。当前固定 `node:24-alpine`，容器无网络且不带 `node_modules`；最多 300 个可访问文本文件、单文件 40,000 字符、验证快照 4 MiB、单命令 60 秒，容器副本中的命令写入会丢弃。
5. 补独立 Runner 分发、图形目录选择和多连接管理；配置并评估真实 RAG；完善费用硬预算、共享锁与并发协调、自动备份及恢复演练。远程外部 Agent/MCP 接入继续作为后续扩展。
